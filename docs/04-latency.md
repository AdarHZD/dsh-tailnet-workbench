# 时延统计与展示

页面里有两个不同的数字，不能混用：

| 数字 | 位置 | 测什么 | 方向 |
|---|---|---|---|
| 设备时延 `xxms` | 设备卡每行 | Mac ↔ 接入设备的网络往返 | 从 Mac 发起 |
| DSH 时延 `xxms` | DSH 视图右上角 | 浏览器 ↔ DSH（经 `:8711` 反代） | 从当前浏览器发起 |

## 设备时延

### 采集

`workbench.py` 对每台在线设备执行：

```bash
tailscale ping -c 2 --timeout 2s <tailnet IP>
```

- 发 2 个包：第一个包常用来刷新路径，可能超时；取两个包里最小的往返；
- 解析 `in Xms` / `in Xs`，四舍五入到整数毫秒；
- 从 `pong from ... via DERP(...)` 判断是否中继：出现 `DERP` 记为 `relay`，否则 `direct`；
- 结果缓存 5 秒；所有设备并发探测，整体最多等 5 秒；
- 探测放在后台线程，`/api/status` 只读上次结果，不把网络等待压到页面请求上。

Tailscale CLI 不可用（被 macOS 权限拦截、未安装）时，退回系统 `ping -c 1 -t 2` 的平均往返；这时拿不到直连/中继，页面不显示路径徽标。

### 为什么用 disco ping

手机/平板在走中继时通常不回应系统 ICMP；`tailscale ping` 走 WireGuard 的 disco 通道，各平台、直连和中继都能测，并且返回实际路径。

不用「设备主动访问工作台接口的 HTTP 往返」来算设备时延：那个数包含服务端采集、浏览器调度和页面渲染，不是纯网络时延。

### 在线判定

满足任一条件即在线：

1. `tailscale status --json` 里 `Online: true`；
2. 该设备的 tailnet IP 在最近 300 秒内请求过工作台（`note_seen`）。

第 2 条是为了兜住「ping 走中继打不通、但人正在用页面」的情况。离线设备显示最后在线时间，时延显示 `—`。

### 阈值

| 区间 | 颜色 | 含义 |
|---|---|---|
| `< 200ms` | 绿 | 直连正常（局域网/同城 IPv6 通常在 1–40ms） |
| `200–349ms` | 黄 | 跨地域直连或中继边缘 |
| `≥ 350ms` | 红 | 明显异常，优先怀疑中继 |

阈值只用于颜色，不改变数值。数值永远显示原始毫秒数，不取整到 10ms，不做移动平均。

### 拿不到时

显示 `—`（`--dim`），不显示 `0ms`、`<1ms`、`超时` 或任何估算值。探测失败只影响这个数字，不影响页面其他部分。

## DSH 时延

`workbench.py` 在状态里下发一个同源探针地址：

```
http://<当前主机>:8711/dsh-cache-helper/api/pending
```

前端在 DSH 视图里每 3 秒 `fetch(url, {mode: "no-cors", cache: "no-store"})`，用 `performance.now()` 量一次完整往返；超过 5000ms 视为失败，显示 `—`。

这个数包含：浏览器调度 + 到 Mac 的网络 + Caddy + DSH 处理。它回答的是「我现在操作 DSH 卡不卡」，不是纯网络 RTT，所以不要和左侧设备时延直接比较。

## IPv6 直连怎么确认

在 Mac 上：

```bash
tailscale netcheck          # 看 IPv6: yes、UDP: true
tailscale ping -c 2 <peer>  # 看 via 后面是地址还是 DERP
```

| 输出 | 含义 |
|---|---|
| `via [2408:...]:41641` | IPv6 直连，最佳 |
| `via 1.2.3.4:41641` | IPv4 直连 |
| `via DERP(...)` | 中继，检查路由器 IPv6 防火墙 / 运营商 |

IPv6 只用于 Tailscale 打洞，不需要端口映射，也不要把 `8710` / `8711` 绑到公网 IPv6。

## 预期量级（参考）

| 场景 | 设备时延 | DSH 时延 |
|---|---|---|
| 同一 Wi-Fi | 1–10ms | 5–30ms |
| 外出手机 IPv6 直连 | 8–40ms | 20–80ms |
| 跨省直连 | 40–120ms | 60–180ms |
| DERP 中继 | 150–400ms | 200–500ms |

超过 350ms 且路径是 `Relay`，先解决直连，不要调阈值。
